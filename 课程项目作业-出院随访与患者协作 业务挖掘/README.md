## 3. 三份文档的核心结论

### 01 业务挖掘

- **触发事件**：心衰患者出院 9 天再入院，随访系统显示"已随访（未接通）"，家属称未被告知需每日称体重。
- **现状基线**：月出院 2 650 人次，应随访 1 930 人次，随访完成率 72.4%（质控口径），30 天再入院率 8.7%（心衰 18.3%）。
- **立项结论**：医务部批 3 个月试点、8 万元预算、心内科 + 呼吸内科两个科室；数据脱敏只读。
- **决策链**：提出（李慧敏）→ 审定（王振国立）→ 合规（孙倩）→ 技术（何嘉）；业务或合规任一方可叫停。

### 02 调研记录

- 6 位角色、285 分钟，含 3 例现场跟访计时；每位都记录了"最近一单"的时间线。
- 5 个矛盾点，其中 3 个已现场裁定（随访完成定义、完成率口径、再入院率口径），2 个保留待核实（出院宣教是否执行、号码完整性）。
- 18 条证据编号，均在后续文档中被引用。

### 03 现场调研分析

- 现状流程 13 步，**主动脉塞点：未接通即标记"已随访"**——异常没有出口。
- 四来源（Buyer / Brief / Industry / Operator）收敛到同一瓶颈：随访"完成"没有可信定义与记录。
- 7 个问题按"损失 × 频率 × 可解决性"排序，选出 P-01/P-02/P-03 作为本轮优先。
- 6 条需求（REQ-01～06）带追溯矩阵、排除范围、人工控制点与可测验收阈值。

## 4. MVP 说明（对应老师第 4 条要求）

### 4.1 FastAPI

11 个接口，覆盖随访计划、记录、统计、问答、管理与审计。

| 方法 | 路径 | 说明 | 权限 |
| --- | --- | --- | --- |
| POST | `/auth/login` | 登录换 token | 公开 |
| GET | `/me` | 当前用户与权限点 | 登录 |
| GET | `/followups` | 随访任务列表（按角色收敛） | 全部角色 |
| GET | `/followups/{id}` | 任务详情 | 数据级鉴权 |
| POST | `/followups/plan` | 按病种生成随访计划 | 医生 / 管理员 |
| POST | `/followups/{id}/records` | 录入随访结果（幂等） | 护士 / 医生 / 管理员 |
| GET | `/stats/completion` | 随访完成率（单一质控口径） | 医生 / 护士 / 管理员 |
| POST | `/qa` | 患者问答（带出处 / 转人工） | 全部角色 |
| GET | `/admin/users` | 用户清单 | 仅管理员 |
| GET | `/admin/audit` | 审计日志 | 仅管理员 |
| GET | `/health` | 健康检查 | 公开 |

### 4.2 知识库 RAG + LLM Wiki（知识图谱）

- **知识库**：4 份院内资料按二级标题切块，BM25 检索（中文单字 + 二元组分词）。
- **知识图谱**：21 条三元组（头实体 / 关系 / 尾实体 / 出处），用于查询扩展和事实补充（如"心衰 → 首次随访 → 出院后 7 天内"）。
- **出处与拒答**：每个回答返回 `sources`（文档 + 章节 + 得分）；命中用药红线或超出服务范围时返回 `need_human=true` 并给出人工联系方式。
- **病种过滤**：问题点名某病种时优先在该病种指导文档内检索，避免制度文档抢占。

### 4.3 权限分层

| 角色 | 可见范围 | 可做操作 |
| --- | --- | --- |
| 管理员（SaaS） | 全租户、全院 | 用户管理、审计查看、跨科室数据 |
| 医生 | 本科室 | 生成随访计划、录入记录、看本科室统计 |
| 随访护士 | 本科室 | 录入随访记录、看本科室统计 |
| 患者 | 仅本人 | 查看自己的随访任务、使用问答 |

数据级鉴权在 `auth.can_read_followup()` 中实现，越权返回 403 并写审计日志。

### 4.4 Harness

`mvp/harness/cases.json` 共 **29 条**用例，分七类：检索正确性（12）、边界与医疗红线（5）、权限（6）、分层规则（3）、统计口径（1）、幂等（1）、异常强制校验（1）。逐条与 REQ 的映射见 [05 §8](05-方案设计与测试评估.md)。

## 6. 评估结果（模拟验证）

以下结果来自 `mvp/harness/run_eval.py` 的实际运行（固定代码快照 + 固定评估集，可复现）：

| 类别 | 通过 / 总数 | 通过率 | 说明 |
| --- | --- | --- | --- |
| 检索正确性 | 12 / 12 | 100% | 库内问题均命中正确病种文档 |
| 边界与医疗红线 | 5 / 5 | 100% | 越界问题拒绝、用药问题 100% 转人工 |
| 权限 | 6 / 6 | 100% | 患者/跨科室越权全部 403 |
| 分层规则 | 3 / 3 | 100% | 高危 7 天、中危 14 天、未知病种待人工确认 |
| 统计口径 | 1 / 1 | 100% | 完成率与制度定义一致，且按角色收敛范围 |
| 幂等 | 1 / 1 | 100% | 同一 `request_id` 重复提交只落一条记录 |
| 异常强制校验 | 1 / 1 | 100% | 未接通未填后续动作被拒（400） |
| **合计** | **29 / 29** | **100%** | 机器可读明细见 `mvp/harness/report.json` |

**验证类型必须如实标注**：以上属于 **模拟验证**（接口层，固定种子数据）。
**口径说明**：`/stats/completion` 基于 12 条演示任务（其中心内科 9 条）计算，用于验证"口径一致 + 角色范围 + 计算正确"，**不等于** 01 文档中全院 Q3 基线 72.4%，两者不可直接比较。
**未覆盖**：真实 HIS 只读接口联调、真实临床大模型调用、真实用户 UAT（阶段 07/08 内容）。
